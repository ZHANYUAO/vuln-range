## 二、为什么把 json-ptr 从 9.1 下修到 7.3（实事求是的关键一条）

11-02 的引擎报告写「全链路 RCE，CVSS 9.1」。复核后的准确表述是：

- ✅ 库**确实**能在读侧返回 `Function` 构造器（实测 `typeof === 'function'`）；
- ❌ 库**不会**自动调用它。`get()` 的返回值交给调用方；调用方若不调用，只是拿到一个函数对象；
- 因此 9.1（AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H）**预设了下游必然调用**，属于未验证假设；
- 本次提交统一改为「库级 7.3 + 明确写出升级条件」，并在报告里注明下游未验证。

> 这不是自我否定，是避免被维护者一句「your app called it」打回。**能被维护者接受的前提，是影响边界比他更保守。**

## 五、本次提交的诚实边界（写给自己看）

1. **三条都未做下游应用利用**。全部是库级行为 + 条件升级说明。
2. `json-ptr` 的 9.1 是旧结论，已下修；不要在任何对外文本里再出现 9.1。

外部报告人**无法**用 token 提交 advisory。所以 token 也救不了 advisory 通道，只能提交 issue。

### 6.2 关键修正：fast-json-patch 是「CVE 修复不完整」，不是「新绕过」

- `GHSA-8gh8-hqwg-xf34` = **CVE-2021-4279**，high 7.3，影响 `< 3.1.1`，**修复版本 3.1.1**
- 修复提交 `7ad6af41eabb2d799f698740a91284d762c955c9`（2021-08-13，PR #262，huntr.dev 报送）
  的 diff 只做了一件事：把 `key == '__proto__'` 扩成
  `key == '__proto__' || (key == 'prototype' && keys[t-1] == 'constructor')`
- 我们测的正是 3.1.1 → 报告定级从「guard bypass」升级为「**该 CVE 的修复不完整**」，
  证据链更硬（补丁 diff 与我们的 payload 一一对应）
- 附带价值：仓库 **#308 正在讨论把该修复 backport 到 v2**，报告里直接建议
  「backport 时修分类不要搬黑名单」，否则 v2 继承同一缺陷

`json-logic-js` 同理：`GHSA-m9hw-7xfv-wqg7`（high）在 **2.0.0** 通过删除 `method` 操作符修复，
我们测的 2.0.5 仍可经 `var` 到达 `Function` → 定位为「同一可达面、另一条路径」。

### 6.4 提交工具

### 6.5 本机凭据现状（决定走哪条）

- `gh` CLI：**未安装**；`~/.config/gh`：无
- `~/.git-credentials`：无；credential.helper：未配置
- 环境变量 `GH_TOKEN` / `GITHUB_TOKEN`：无
- Edge 已登录 GitHub，但 **cookie 为 app-bound 加密**（`Local State` 含 `app_bound_encrypted_key`），
  且浏览器正在用默认 profile 运行 → **既无法解出 cookie，也无法挂调试端口**
- 结论：**token 是唯一全自动路径**；否则就是「预填 URL + 人点一次 Submit」

### 6.6 披露口径（因 PVR 缺失而调整）

原 advisory 里写的是「先私下汇报、45 天内不公开」。PVR 关了 → 私密通道**不存在**，
所以正文改为：**给出最小可复现（一行原语）+ 明确请求开启 PVR 或提供私密联系方式**，
完整 harness 与全量逃逸段集合**留到私密通道建立后再给**。这不是缩水，是在没有私密通道时
唯一既负责任、又能让对方独立验证的姿态。
