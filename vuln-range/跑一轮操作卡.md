### 目标（直接复制）

```

逐项验证可利用性并产出 finding。每个 finding 必须附带可复现的

【执行环境 — 必须遵守】

- 禁止使用 curl、wget、nc 等 bash 语法（PowerShell 里 curl 是
  Invoke-WebRequest 的别名，参数不兼容，会直接报错）

  python -c "import urllib.request;print(urllib.request.urlopen('http://127.0.0.1:8899/',timeout=8).read().decode()[:800])"
  python -c "import urllib.request as u;print(u.urlopen('http://127.0.0.1:8899/admin',timeout=8).status)"
- 需要带参数/自定义头时用 python 的 urllib.request.Request
- python 可用，requests 可能未安装，优先用标准库 urllib
```

## Windows 上的坑（已实测）

ARTEX 的 agent 只有一个 `bash` 工具，但 norma 在 Windows 上**实际执行的是 `powershell -NoProfile -NonInteractive -Command`**
（`tool/task.go: shellCmd()`）。后果：

- 模型习惯性写 `curl -s -I http://...` → 参数是 bash 风格，PowerShell 下报错
- PowerShell 5.1 里 `curl` 是 `Invoke-WebRequest` 的别名，不是真 curl
- 实测 `python -c "print(6*7)"` → 返回 42，**python 这条路是通的**

所以任务描述里的环境约束不是可选的，不加的话 agent 会在 curl 上反复撞墙浪费轮次。
