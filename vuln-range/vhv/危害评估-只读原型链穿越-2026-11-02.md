# 危害评估：只读原型链穿越（lodash 家族）

> 实测环境：Node v22.22.2 / lodash 4.18.1 / lodash.get 4.4.2 / lodash.invoke 4.5.2
> 生成器：`impact_probe.js`　证据：`cases/impact-probe.json`（HIT 22 / MISS 4 / NA 0）
> 日期：2026-11-02

---

## 一、一句话结论

**这是一个「path 可控即任意代码执行」的原语；它不是信息泄露级缺陷，但也不是无条件 RCE。**
危害的开关只有一个：**攻击者能不能决定传给 `_.get` / `_.invoke` 的那段 path**。
这个开关在 Web 应用里极少打开（8 个真实应用实测 0 命中），但在**沙箱、规则引擎、字段投影适配层**里几乎必然是打开的。

---

## 二、能力阶梯：从「读到」到「做到」逐档实测

| 档 | 能力 | 实测 | 证据 |
|---|---|---|---|
| L0 | 读 `Function` 构造器本体 | **HIT** | 4 形态全通：`_.get` / `lodash.get` / `_.at` / `lodash/fp.get` |
| L1 | 执行任意 JS 表达式 | **HIT** | `Function('return 6*7')()` → `42` |
| L2 | 取出 `process` 对象 | **HIT** | `pid=7116` 实际取到 |
| L3 | 读任意文件 | **HIT** | `fs.readFileSync` 读到 583 字节 |
| L4 | 起子进程执行系统命令 | **HIT** | `execSync('echo ...')` → `IMPACT_PROBE_OK` |
| L5 | 枚举环境变量（凭据） | **HIT** | 219 项，含 token / 数据库口令的典型位置 |
| L6 | 主动出网（反弹 shell 前提） | **HIT** | `net.connect` 可用（未实际连接） |
| L7 | 拒绝服务 | **HIT** | `_.invoke(process,'exit',7)`，宿主退出码 7 |
| L8 | 升级为原型污染（写） | **HIT** | 借 Function 写 `Object.prototype`，全对象可见 |

**L3–L6 合起来就是完整 RCE，不是"能执行一个表达式"。**
从 `_.get(obj, path)` 到拿到 shell，攻击链是：

```js
const F = _.get({}, '__proto__.constructor.constructor');  // 你只给了这一段
// —— 以下全部由攻击者的字符串完成 ——
F('return process')().mainModule.require('child_process').execSync('id');
```

## 三、关键约束：path 可控的粒度决定成败

真实代码里 path 很少整串可控，常见的是拼接。四种拼接方式实测：

| 拼接形态 | 例子 | 结果 |
|---|---|---|
| 整串可控 | `_.get(cfg, input)` | **HIT** |
| 前缀固定 + 输入 | `_.get(cfg, 'user.' + input)` | **HIT**（前缀被吃掉） |
| 深前缀固定 | `_.get(o, 'a.b.c.' + input)` | **HIT**（三段前缀照样穿） |
| 数组单段可控 | `_.get(cfg, ['user','profile', input])` | **HIT** |
| **后缀固定** | `_.get(cfg, input + '.x')` | **MISS** ← 唯一打不通的形态 |

**这条边界很重要**：`input + '.固定后缀'` 才是真安全，因为它让 path 必须以一个不存在的属性结尾，`undefined` 一取就断。
凡"用户输入拼在中间或末尾"的写法，一律不安全。

## 四、已有防护时的绕过（决定危害是否存在于"加固过的"应用）

| 防护措施 | 是否有效 | 实测 |
|---|---|---|
| 只过滤 `__proto__` | ❌ **无效** | 改用 `constructor.constructor`，payload 完全不含 `__proto__` |
| 只过滤 `__proto__` | ❌ **无效** | `toString.constructor` 也可，两个词看起来都不像攻击词 |
| 字符串黑名单 + 数组 path | ❌ **无效** | 校验器写 `typeof p === 'string'` 时数组直接跳过 |
| **双黑名单（`__proto__` + `constructor`）** | ✅ **有效** | 5 条候选路径全部被封，RCE 档确实打不开 |
| 大小写 / URL 编码变体 | ❌ 无效 | `__PROTO__`、`%5F%5F` 全不成立 —— lodash 不做解码，**别指望变体** |

结论：**同时 deny `__proto__` 和 `constructor` 是有效的最小缓解措施**；只 deny 一个是心理安慰。
但即使双黑名单生效，宿主原型上的函数对象仍然可达（信息暴露面留存），只是升不到执行。

## 五、真实危害场景排序（按"path 必然可控"的概率）

| 排名 | 场景 | 为什么必然可控 | 后果 |
|---|---|---|---|
| **1** | **JS 沙箱 / 插件系统**（规则引擎、低代码表达式、模板渲染） | 沙箱的存在前提就是"允许不可信输入指定访问路径" | 沙箱逃逸 = 沙箱意义归零。这是本漏洞最致命的位置 |
| 2 | 适配层（JSONPath→lodash、GraphQL→lodash、Mongo 投影） | 职责就是把外部路径语法翻译成 lodash path | 翻译层直接变成 RCE 入口 |
| 3 | 通用取值 API（`/api/value?p=...`） | path 就是接口参数 | 单请求 RCE |
| 4 | 字段投影（`?fields=a,b,c`） | 用户指定返回哪些字段 | 若用 `_.get(row, f)` 逐个取，可控 |
| 5 | 供应链 | `lodash.get` 周下载 2232 万、0 advisory | 下游无条件继承该原语，SCA 不报警 |

**Web 应用本体反而排在最后** —— 实测 8 个大应用（Ghost / Strapi / Directus / n8n / NocoBase / Apostrophe / Parse Server）共 6457 文件，HTTP 级可达 **2 处，人工核查后成立 0 处**。
这不是说漏洞不严重，而是说**上一轮的测量场景选错了**：我测的是"应用有没有把 path 交给用户"，该测的是"沙箱有没有把 path 交给用户"。

## 六、做不到什么（诚实边界，披露时必须主动说）

1. **不能在没有 path 控制权时利用。** 硬编码字面量 `_.get(obj,'a.b.c')` 占绝大多数用法，完全不受影响。
2. **不能直接写入。** `_.get` 本身零写入（实测对照 MISS）；要写必须先拿到 Function 并被调用一次。
3. **后缀固定的拼接打不通。**
4. **不能靠编码/大小写变体绕过黑名单。**
5. **不是无条件 0day。** 它是"库里有缺陷"（确定），加上"调用方暴露 path"（条件），合起来才是"应用有漏洞"。当前证据止步于前一半。

## 七、定级建议

| 视角 | CVSS | 说明 |
|---|---|---|
| 库级（`lodash.get` 包本身） | **8.1 High**　`AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H` | AC:H 就扣在"需要调用方暴露 path" |
| 应用级（确认 path 可控时） | **9.8 Critical** | AC 降为 L，其余拉满 |
| 沙箱逃逸场景 | **≥9.8**（建议 `S:C`） | 影响范围从沙箱扩散到宿主进程 |

**不建议按 Critical 对外宣称**——在没有真实应用 PoC 的情况下，维护者一句"实际不可达"就能驳回，而我们自己的 0/8 数据正好给人递刀。按 High + 主动披露可达性测量，反而堵死这条退路。
