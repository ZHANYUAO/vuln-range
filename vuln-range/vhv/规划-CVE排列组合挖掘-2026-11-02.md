# 从历史 CVE 到新 CVE：一套可执行的排列组合方法

生成时间：2026-11-02
配套产物：`cve-db/index.json`（47 条 advisory）、`combo_matrix.py`（覆盖矩阵）、
`enumdists.js` + `distcheck.mjs`（分发形态矩阵）

---

## 0. 一句话结论

**历史 CVE 不是一堆孤立的洞，它们是「已经被占用的格子」。**
一个格子 =（某个函数）×（某个防护承诺）×（某个分发形态）×（某个触发形态）。
防护承诺是有限可枚举的，而位置和形态是组合爆炸的 —— 空格子必然存在，
而且没人系统扫过。我们要做的不是「更聪明地猜」，而是**把空格子算出来，再逐个证伪**。

这个方法的有效性已经有一个硬证据：矩阵自动标出 `get` / `invoke` / `invokeMap` /
`method` / `methodOf` / `at` 六个函数「从未被任何 CVE 覆盖」，而它们正好是本项目
已实测打穿的那批。**工具独立地走到了和我手工探索相同的结论。**

## 1. 先摆数据：这个领域有多空

从 OSV 拉了 24 个 npm 包的 47 条 advisory，其中 `lodash` 一家 10 条，
构成一条跨 8 年的完整修复链：

| 修复版本 | CVE | 修的是什么 | 下一轮怎么被绕过 |
|---|---|---|---|
| 4.17.5 | CVE-2018-3721 | merge / defaultsDeep 的 `__proto__` | `constructor.prototype` |
| 4.17.11 | CVE-2018-16487 | 上一轮修复不完整 | — |
| 4.17.12~14 | CVE-2019-10744 | defaultsDeep 深路径 | — |
| 4.17.19/20 | CVE-2020-8203 | zipObjectDeep / set 的路径 | **数组形式 path** |
| 4.17.23 | CVE-2025-13465 | `_.unset` / `_.omit` 的 array path | **同语义的另一个函数** |
| 4.18.0 | CVE-2026-2950 | array path bypass（同一处再修） | **`_.invoke` 家族（未修，本项目发现）** |

覆盖矩阵的统计（34 个 path 相关函数 × 5 类不变量 = 170 格）：

```
已占用格子: 14     空格子: 156     覆盖率 8.2%
```

**92% 的格子是空的。** 这不是说 156 个格子都有洞 —— 是说没人系统检查过它们。

## 2. 历史 CVE 到底是怎么被发现的

把 47 条按发现机制归类，直接决定哪些能自动化：

| 机制 | 占比（估） | 典型例子 | 可自动化 | 我们的工具覆盖 |
|---|---|---|---|---|
| **已知模式人工审计** | 最高 | 各种 merge 原型污染 | 部分 | ✅ guardcov / locate |
| **补丁回归 / 变体分析** | 中 | CVE-2018-16487（修 3721 不彻底） | **高** | ✅ VHV 回路 |
| **Fuzzing / 差分测试** | 中 | flat、minimist 的解析崩溃 | 中 | ❌ 未做 |
| **静态规则扫描** | 低 | Semgrep/CodeQL 规则命中的 | 高 | 部分（guardcov 是自研静态） |
| **依赖投毒 / 供应链观察** | 低 | 恶意包，非本类 | 低 | ❌ 不做 |

**关键观察**：占最大头的「已知模式人工审计」恰恰是最容易转成组合算子的 ——
因为它有明确的「模式」，模式就是不变量的来源。

## 3. 为什么「排列组合」不是玄学

你说「按辩证法任何系统一定能找到漏洞」。这话可以做成一个可计算的命题，而不是口号。

### 3.1 形式化

候选空间 = **不变量 I × 位置 P × 分发形态 D × 触发形态 F**

| 维度 | 基数 | 是否有限可枚举 | 来源 |
|---|---|---|---|
| I 不变量 | ~5（禁 `__proto__` / 禁 `constructor` / 禁 `prototype` / 仅自有属性 / 不可变） | 是 | 从 patch 提取 |
| P 位置 | 34（lodash path 相关函数） | 是 | AST（locate.js） |
| D 分发形态 | 23（主包/单方法包/-es/fp/子路径） | 是 | enumdists.js |
| F 触发形态 | ~6（字符串 path / 数组 path / merge 对象 / 编码 / 嵌套 / getter） | 是 | 从 advisory 提取 |

四个维度都有限，所以**组合空间是有限的、可枚举的**。
`34 × 23 × 6 ≈ 4700` 个格子，历史 CVE 占了 14 个。

### 3.2 辩证法的部分：为什么「修完还会出」

这不是维护者无能，是结构性的：

- **正题**：功能要求 path 能走任意键（`a.b.c`、数组、点号）
- **反题**：安全要求挡住危险键（`__proto__`、`constructor`、`prototype`）
- **合题**：在「能走任意键」的前提下挡住危险键 → 必然依赖一份**黑名单**
- **新矛盾**：黑名单的**边界**永远不完整 —— 挡了 `__proto__` 漏 `constructor.prototype`；
  挡了字符串 path 漏数组 path；挡了 `unset` 漏 `invoke`

所以「修复→绕过」不是偶发事件，是**合题内含新矛盾**的必然结果。
lodash 8 年 6 次修复，每一次都精确落在上一轮黑名单的边界外 —— 这个规律本身就是论证。

**这条正好能支撑论文的 motivation**：不是「又有漏洞」，而是「黑名单式修复在结构上无法收敛」。

## 4. 六个组合算子（核心）

每个算子都是「拿两个已有格子，生成一个新格子」。

### 算子 1：同位置 × 异不变量 —— 防护不全

**定义**：某函数挡了不变量 A，但做同样穿越动作时不变量 B 没挡。
**已验证**：`baseUnset` 挡了 `__proto__`，`baseInvoke` 一个都没挡 → `_.invoke` RCE。
**产出**：guardcov 的 `partial_keys` 信号。
**成本**：极低（工具已能出）。

### 算子 2：同不变量 × 异位置 —— 变体传播

**定义**：修了函数 A 的穿越，做同样穿越的函数 B/C/D 没修。
**已验证**：全库 4 处 guard，`safeGet` 只被 merge 家族调用（3 次），
`baseGet` / `parent` / `baseInvoke` 调用 0 次 —— **锁造好了只装在一扇门上**。
**产出**：`locate.js` 的反向可达 + `guardcov.js` 的调用点覆盖率。
**成本**：低。

### 算子 3：同不变量 × 异形态 —— 分发断层

**定义**：修复进了主包，没进按方法拆分的独立包 / ESM / fp。
**已验证**（本轮 P1 自动化的结果）：

| 形态 | 版本 | get | set | invoke | at |
|---|---|---|---|---|---|
| `lodash` 主包 | 4.18.1 | HIT | 挡住 | HIT | HIT |
| `lodash.get` | **4.4.2（2016）** | HIT | — | — | — |
| `lodash.set` | **4.3.2（2016）** | — | **HIT** | — | — |
| `lodash/invoke` 子路径 | 4.18.1 | — | — | HIT | — |
| `lodash/fp/invokeArgs` | 4.18.1 | — | — | **HIT** | — |
| `lodash-es` | 4.18.1 | HIT | 挡住 | HIT | HIT |

**这是本轮最硬的新证据**：同一个逻辑操作，主包已修，单方法包 8 年没动。
`lodash.get` 周下载 **2230 万**、OSV advisory 数 **0**、可拿 `Function` 执行。

**成本**：低（`enumdists.js` + `distcheck.mjs` 已自动化）。

### 算子 4：同不变量 × 异生态 —— 跨语言移植

**定义**：JS 里被修的形态，在 Python/Go/Rust 的对应库里是否存在。
**待验证**：`dotty` / `glom`（Python）、`gjson` / `sjson`（Go）。
**成本**：中（要重写载荷适配层，但判定逻辑可复用）。
**价值**：这是把「一个库的问题」升级成「一类设计缺陷」的唯一路径，论文必须。

### 算子 5：修复模式 × 绕过模式 —— 黑名单的边界

**定义**：上一个 CVE 的修复用了什么判据，这个判据的反面就是新载荷。
**这就是 lodash 8 年链的驱动机制**，已整理成词典（见第 5 节）。
**成本**：低（有 patch 就能提取）。
**这是最高产出的算子** —— 历史上 6 次里至少 4 次是这么来的。

### 算子 6：两 CVE 修补的交集 —— 组合缺口

**定义**：CVE-A 修了位置 X，CVE-B 修了位置 Y，那么「经过 X 且经过 Y」的路径
可能两个 guard 都不覆盖。
**例子**：`_.invoke` 的 path 既走 `castPath`（被 CVE-2026-2950 修过）+ 又走 `parent`
（从没被修过）→ 组合起来就是新洞。
**产出**：调用图上的「双经过」节点。
**成本**：中（需要 call path 枚举）。

## 5. 绕过模式词典（从修复链提取，这是算子 5 的弹药）

| 修复的承诺 | 绕过手法 | 对应 CVE |
|---|---|---|
| 挡住 `__proto__` 键 | 走 `constructor.prototype` 等价链 | CVE-2018-16487 |
| 挡住字符串 `"__proto__.x"` | 传数组 `['__proto__','x']` | CVE-2020-8203 / 2026-2950 |
| 挡住顶层 `__proto__` | 嵌套 `a.__proto__.x` | CVE-2020-36632（flat） |
| 挡住 `unset` / `omit` | 同语义的 `invoke` / `set` 没挡 | **本项目（未公开）** |
| 只挡 proto 键 | `constructor` 也是函数 → `constructor.constructor` = `Function` | **本项目（未公开）** |
| 修主包 | 单方法包独立发版，停在 8 年前 | **本轮新发现** |

**这个词典可以自动化生成**：把每个 CVE 的 patch diff 拿出来，提取新增的条件判断里的
键字面量和位置，取反就是绕过候选。`seed.py` 已经有 patch 抓取能力，缺的是「取反」这一步。

## 6. 执行路线

### P0 — 候选清单（**本轮已完成**）

| 产出 | 状态 |
|---|---|
| 历史 CVE 库（47 条 / 24 包） | ✅ `cve-db/index.json` |
| 覆盖矩阵（34 函数 × 5 不变量） | ✅ `combo_matrix.py` |
| 分发形态矩阵（23 形态） | ✅ `enumdists.js` + `distcheck.mjs` |
| 候选集 | ✅ 23 个函数从未被 CVE 覆盖 |

### P1 — 候选过滤（1 天，零风险）

矩阵的 23 个空格里**混着假空格**（例如 `merge`：明明有 CVE-2018-3721，但 advisory
文本没写 `_.merge` 这个词）。所以空格子只是候选，必须过三道闸门（第 7 节）。

产出：23 → 真实的「无 CVE 覆盖 + 结构可达」清单（预计 8-12 个）。

### P2 — 逐个证伪（2-3 天）

对 P1 的每个候选跑 VHV 回路：结构核对 → 强制可执行化 → 双版本反事实。
参照 `_.invoke` 的流程，单条成本约 1-2 小时。

**已完成的 7 个**：get / invoke / invokeMap / method / methodOf / at（真）+
merge 家族（假，ineffective）。

### P3 — 绕过词典自动化（2 天）

把 47 条 CVE 的 patch 拉下来，自动提取「修复判据 → 取反 → 绕过载荷」。
这是算子 5 的工程化，也是**唯一能持续产出新候选的自动化路径**。

### P4 — 横向铺开（1 周）

- 同生态：object-path / jsonpointer / dset / dot-prop 全 API 扫一遍
- 跨生态：Python `dotty`/`glom`、Go `gjson`/`sjson`

### 优先级建议

**P1 → P3 → P2 → P4**。

理由：P1 成本最低且决定后面值不值得做；P3 是唯一能「批量生产候选」的环节；
P2 单条成本高，应该等 P3 给出高价值候选后再做；P4 是为论文服务的，最后做。

## 7. 三道闸门（每个候选必须全过）

| 闸门 | 问题 | 工具 | 不通过的后果 |
|---|---|---|---|
| **① 历史核对** | 是否真的没有 CVE 覆盖？ | `combo_matrix.py` + 人工查 OSV | 假空格 —— `merge` 就是这样被识破的 |
| **② 结构核对** | 该位置是否真的触达 path sink？ | `locate.js`（AST 反向可达） | 只是碰巧调了 `castPath`，不是穿越 |
| **③ 运行时反事实** | 打穿了吗？修好版还能打穿吗？ | `probe.js` + `reify.py` | `ineffective` —— 载荷没打到，不是漏洞 |

**第三道闸门必须用可执行 marker 判据**，不能看返回值形态。
这个坑我自己踩了三次（删除型用写入判据 → 假阴性 22/22；`false` 当已修复；
用"返回值是否 undefined"判封堵 → 一度得出 3/8）。已写进铁律。

## 8. 诚实边界（必须先说，不能等审稿人问）

1. **矩阵的「空格子」不等于「有洞」**。170 格里 156 空，但绝大多数是安全的 ——
   空只代表没人检查过。`merge` 就是假空格的反例（文本提取召回不全）。
2. **文本提取有天花板**。advisory 描述千差万别，正则召回不完美。
   **根本解法是从 patch diff 提取不变量**（P3），不是把正则写得更复杂。
3. **组合空间有限 ≠ 都能利用**。`_.get` 能读穿，但下游不调用它就是信息泄露；
   `fp` 形态能打穿，但 fp 用户极少。**可达性（source）才是价值上限**，
   这是本方法目前最大的缺口 —— 所有结论都停在「库里有问题」，没到「应用有漏洞」。
4. **这是变体挖掘，不是凭空发现**。种子永远是公开 patch。真实价值在
   「未被 advisory 覆盖 + 最新版仍存在」，不在「手法新颖」。
5. **`merge` 家族的判定是 `ineffective`（没打到），不是 `fixed`（已修好）**。
   这两者绝不能混 —— 混了就是把「我不知道」写成「它是安全的」。

## 9. 这个框架对论文意味着什么

现有工作（DNA, EuroSec'26）做的是「patch → 候选定位」，止于人工分诊。
而 arXiv:2608.09567 审计发现：LLM/agent 产出的 oracle 特异性只有 45%，
30 个 patched 反事实审计里 20 个在**已修复版本上仍报信号**。

我们的差异化就在这里：**不是更快地找候选，是把裁决本身自动化** ——
四值判定（HIT / MISS / SHAPE / 未判定），其中「未判定」是一等公民，
专门用来拒绝把「没测到」写成「安全」。

本篇的第 3 节（辩证法 → 黑名单不可能收敛）可以成为 motivation 的理论骨架：
**不是「维护者又漏了」，是「黑名单式修复在结构上无法收敛」**。
这个论点无法被「设计如此」反驳，也无法被「下一个版本修好了」推翻。
